Hermes is at its best when it lives on a server with your skills and your memory. But the work is on your laptop: the files, the local services, the credentials that never leave the machine. SSH just moves the command to the wrong machine. Copying secrets to the VPS is worse. Sidecar splits the runtime, not the trust. The remote Hermes keeps the brain; a paired local daemon is the hands. Every terminal and file-tool command travels over an authenticated connection, one command at a time. By default, anything that is not a harmless read-only command waits for you. You see the exact command, and you approve or deny it. A deny list stops privilege escalation, root deletes, Apple Events, keychain access and download-to-shell. The local command gets a sanitized environment: no provider keys, no SSH agent. Every decision is written to a local audit log. Here is the real demo: a remote brain lists the local workspace, reads a local file, writes a new one, and tries an Apple Events escape hatch. The first four commands wait for approval on this Mac; the last is denied outright. The remote agent only receives the output. Verify it with hermes sidecar verify: eight checks, one command, forty-four tests, and zero Python dependencies. Remote brain, local hands. Sidecar, for the Hermes Agent Plugin Hackathon.
